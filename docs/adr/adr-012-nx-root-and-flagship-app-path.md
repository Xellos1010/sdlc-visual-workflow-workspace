# ADR-012: Nx root scaffold and `flagship-foundry-work` → `apps/flagship-foundry` layout lock

**Status**: accepted — approved 2026-03-24; WO-NX-001..006 complete
**Date**: 2026-03-24
**Work order**: WO-NX-000 (`nx-migration-architecture-lock`)
**Principle**: `approval-at-plan-boundary`, `artifact-authority`, `blast-radius-before-build`

---

## Context

The SDLC workspace (`SDLC - Visual - Workflow - SoftwareEngineering-NewAge`) has no root `package.json`, `nx.json`, or `pnpm-workspace.yaml`. Flagship Foundry lives at `flagship-foundry-work/` with its own Node layout (`apps/*` × 5, `packages/*` × 3) and an existing `pnpm-lock.yaml`. The intent is to make the workspace root a valid Nx + pnpm monorepo with Flagship Foundry as the primary application under `apps/`.

Three structural decisions must be locked before any file moves (WO-NX-001 onward) to avoid rework.

---

## Decision A — Layout: single-folder `apps/flagship-foundry`

**Chosen**: retain Foundry as a **single Nx application** at `apps/flagship-foundry`, preserving its internal `apps/` and `packages/` sub-tree unchanged.

**Rejected alternative**: flatten internal packages (`packages/core`, `packages/model-gateway`, `packages/runtime-adapters`) and apps into root-level Nx projects.

**Rationale**:
- Eight internal units share tightly coupled relative paths to `examples/`, `state/`, `guardrails/`, and each other. Flattening requires updating all these references — a separate, higher-blast-radius slice.
- The `flagship-foundry-work/package.json` already declares `"name": "flagship-foundry"`, making the Nx project name `flagship-foundry` natural with no rename.
- Single-folder approach is the minimum-viable migration; flattening is an explicit opt-in for a future work order.

**Nx project name**: `flagship-foundry`
**Canonical path post-migration**: `apps/flagship-foundry/`

---

## Decision B — Package manager: pnpm at root

**Chosen**: **pnpm** with a root `pnpm-workspace.yaml`.

**Rationale**:
- `flagship-foundry-work/pnpm-lock.yaml` confirms pnpm is already in use inside Foundry — no package manager change required.
- Workspace definition at root: `packages: ["apps/*"]` (picks up `apps/flagship-foundry` as a workspace member).
- The Foundry sub-workspace (`apps/flagship-foundry/package.json`) continues to manage its own `packages/*` internally; root pnpm wraps it as a workspace member, not a replacement.

**Root workspace glob**: `apps/*`
**Lockfile strategy**: root `pnpm-lock.yaml` (generated by `pnpm install` at root in WO-NX-001); existing `flagship-foundry-work/pnpm-lock.yaml` becomes the inner lockfile at `apps/flagship-foundry/pnpm-lock.yaml` after `git mv`.

---

## Decision C — CI `working-directory` strategy

**Chosen**: path-only swap; no behavioral changes to CI gates until WO-NX-005.

**Changes required in `.github/workflows/flagship-foundry-ci.yml`** (deferred to WO-NX-005):

| Field | Before | After |
|-------|--------|-------|
| `paths` filter (push/PR) | `flagship-foundry-work/**` | `apps/flagship-foundry/**` |
| `defaults.run.working-directory` | `flagship-foundry-work` | `apps/flagship-foundry` |
| Install step | `npm install` | `npm install` (unchanged; pnpm root install is separate) |
| Test gates | `npm test`, `npm run ci:targeted` | unchanged for this slice |

**Future improvement** (WO-NX-004 / WO-NX-005): Promote CI gates to `pnpm exec nx run flagship-foundry:test` and `pnpm exec nx run flagship-foundry:ci-targeted` from root, eliminating the `working-directory` override entirely.

---

## Consequences

- **WO-NX-001** can proceed immediately: scaffold root `package.json` (private, no `name`), `pnpm-workspace.yaml` (`packages: ["apps/*"]`), `nx.json`.
- **WO-NX-002** follows: `git mv flagship-foundry-work apps/flagship-foundry`.
- **WO-NX-003** wires root pnpm workspace; inner Foundry `pnpm-lock.yaml` is preserved.
- **WO-NX-004** adds `apps/flagship-foundry/project.json` with `test` and `ci-targeted` targets.
- **WO-NX-005** updates CI paths, root README, `setup.sh`, and continuity JSON.
- Flattening internal packages into root-level Nx projects is **out of scope** for this migration stream; defer to a named follow-on work order.
