Identity & Registration Model

How a user gets an account determines how artifacts bind to people, teams, and repos — and how the confidence loop attributes decisions.

A

GitHub OAuth (Primary)

Sign in with GitHub. Repos are auto-discovered and linkable in one click. Team membership inherits from GitHub org/repo collaborators. No separate invite flow needed — if you have repo access, you're in.

✓ Zero onboarding friction for devs ✓ Repo context automatic ✓ Team sync via org ⚠ Non-GitHub users excluded
B

Email + Workspace (Multi-Provider)

Register with email. Create a named workspace, invite members by email. OAuth providers (GitHub, Google) supported as login methods but not required. Works for any team regardless of toolchain.

✓ Universal — any team ✓ Workspace = collaboration boundary ⚠ Slightly more setup
C

GitHub Primary + Email Fallback

GitHub OAuth is the fast path — one click, workspace auto-created from org. Email/password available for teams not on GitHub. Both paths land in the same workspace model. Best of both.

✓ Developer-optimized fast path ✓ Universal fallback ✓ Unified workspace model
How identity flows into artifacts
User registers → Workspace created → Skill auth token generated → All events tagged with user + workspace → Confidence loop attributes decisions correctly
