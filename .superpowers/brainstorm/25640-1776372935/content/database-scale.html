Database Strategy: Start Fast, Scale Right

PostgreSQL is the right paradigm throughout — Aurora is PostgreSQL-compatible, so Phase 1→2 is a connection string, not a rewrite. ML scale adds purpose-built layers on top.

PHASE 1 Supabase — Prove the Product
Now → product-market fit
POSTGRES (managed)
Events, artifacts, decisions, workspaces, confidence scores
REALTIME
Built-in WebSocket broadcast — zero config team sync
AUTH
GitHub OAuth + email, row-level security, JWT
STORAGE
Artifact files, diagrams, generated code bundles
⚡ pgvector extension available now — confidence embeddings, semantic artifact search work from day one
↓ product has legs
PHASE 2 AWS Aurora PostgreSQL — Production Scale
Full AWS migration
AURORA POSTGRESQL SERVERLESS V2
Same schema, same queries. Auto-scales 0→128TB. 5× faster than standard Postgres. Multi-AZ.
REALTIME LAYER
AWS API Gateway WebSockets or custom Rust WebSocket server (tokio-tungstenite). Replaces Supabase Realtime.
AUTH
Amazon Cognito (GitHub + email) or self-hosted Auth.js. Same JWT model.
STORAGE
Amazon S3 (unlimited, cheap, durable). CloudFront CDN for artifact delivery.
⚡ Migration = connection string swap + Supabase Realtime replacement. Schema unchanged. Zero data model rewrite.
↓ ML training data accumulates
PHASE 3 Full AWS Data Platform — Model Training Scale
When the intelligence loop needs its own infra
AURORA (hot data)
Active workspaces, live events, confidence scores, approval decisions
REDSHIFT (cold / analytics)
Full decision history, aggregate confidence trends, cross-workspace training corpus
OPENSEARCH (semantic)
Vector search across artifacts, specs, diagrams. "Find similar runbooks." Community template discovery.
SAGEMAKER (models)
Train confidence models on aggregate decision corpus. Fine-tune generation models on community templates.
⚡ Aurora → Redshift sync via AWS Glue (automated ETL). No manual migration — data flows forward continuously.
The key: PostgreSQL is the common thread

Supabase is managed PostgreSQL. Aurora is PostgreSQL-compatible. Your schema, queries, and ORM work identically across all three phases. pgvector runs on all of them — the confidence embeddings you build in Phase 1 work in Phase 3 without modification. You are never locked in.
