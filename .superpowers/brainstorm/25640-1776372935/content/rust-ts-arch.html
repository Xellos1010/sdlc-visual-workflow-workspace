TypeScript + Rust: Split by Responsibility

TypeScript is not a ceiling — it's a boundary. The agent runner, orchestration engine, and confidence loop belong in Rust. TypeScript handles the surfaces that require it.

required surfaces
Claude Code Skills
Claude Code constraint — JS/TS only. Thin layer: invoke, display visual companion, emit events.
Web App UI
Next.js 14 — browser is the bottleneck, not the language. React, Tailwind, shadcn.
API Gateway (thin)
Auth, session, routing requests to Rust services. Next.js API routes or lightweight proxy.

Rust
where performance is the feature
Agent Runner / Orchestration Engine
Tokio async runtime — schedules work orders, coordinates agent teams, manages task state, handles failures and retries. Sub-millisecond task dispatch.
Event Processor
Consumes Supabase Realtime stream, routes events to subscribers, enforces workspace isolation. Zero-copy parsing with serde.
Confidence Engine
Aggregates decision history, computes confidence scores, applies threshold rules. High-frequency reads/writes — Rust keeps this hot.
Generation Pipeline
Artifact → target framework code gen. TDD test runner integration. Dependency-aware failure aggregation. IR parsing.
Diagram & IR Engine
Repo ingestion, symbol graph extraction, pseudocode normalization. Parallelized with Rayon. Results streamed back via gRPC.
SHARED LAYER
Supabase Postgres (event store + artifact registry) Supabase Realtime (broadcast channel) Supabase Storage (artifact files)
WHY TYPESCRIPT IS NOT A PERFORMANCE PROBLEM
  • → Skills are thin invocation wrappers — they call Rust services, not compute themselves
  • → Web UI is browser-bound — JS perf is irrelevant at that layer
  • → Auth/routing is I/O-bound — latency is network, not CPU
WHY RUST IS THE RIGHT CHOICE FOR THE CORE
  • → Agent orchestration is CPU + memory intensive — Tokio handles thousands of concurrent tasks
  • → Confidence loop is hot path — computed on every decision, needs to be fast
  • → IR / symbol graph parsing is parallelizable — Rayon saturates all cores
  • → You already have the rust-porter pipeline — the codebase is already Rust-ready
