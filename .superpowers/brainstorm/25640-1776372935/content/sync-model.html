What triggers the sync?

A

Event-Driven Sync

Specific lifecycle events trigger sync — spec published, diagram saved, approval decision made, test run completed, runbook activated. Nothing syncs until a meaningful action occurs. Cloud reflects intentional state, not file churn.

✓ Clean audit trail ✓ Intent-aligned ✓ Approval gates natural fit
B

Always-On Background Sync

Everything in the workspace directory syncs continuously in the background — like Dropbox for your AI artifacts. Every file write propagates. Team sees changes in near real-time without any explicit action.

✓ Zero friction ⚠ Noisy for team ⚠ Harder to version
C

Git-Like Explicit Push

User or skill explicitly publishes a snapshot — like a commit. Artifacts batch together with a message, version, and intent label. Team reviews published states not intermediate work.

✓ Predictable versions ✓ Team clarity ⚠ Manual step breaks flow
💡 My recommendation: A (Event-Driven)

Event-driven sync maps directly to the approval pipeline model — every meaningful state change is already an event. The confidence loop needs clean decision events, not file diffs. And it keeps the web app as a curated view of intent, not a mirror of filesystem noise.
