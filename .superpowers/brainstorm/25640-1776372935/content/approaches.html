Three Architecture Approaches

Same destination — different build order and tradeoffs. Pick the one that matches how you want to prove value fastest.

A

Nx Monorepo — Skills First, Everything Together Recommended

One repo. Skills prove the loop first. Web app and Rust services added in the same workspace. Nx handles affected builds — change a Rust crate, only that crate rebuilds.

PHASE 1 — PROVE
Skills + visual companion
Hello world loop
Local artifact sync
PHASE 2 — CONNECT
PAL + AWS infra
Event-driven sync
Auth + workspaces
PHASE 3 — ACCELERATE
Rust agent runner
Confidence engine
IR pipeline
PHASE 4 — SCALE
Web app + collab
Marketplace
ML training loop
✓ You already have an Nx workspace ✓ Skills testable in minutes ✓ Rust crates + TS apps coexist ✓ Nx affected = CI only runs what changed ✓ One place to find everything
B

Polyrepo Services — API First

Separate repos for each service: skills repo, web-app repo, agent-runner repo. Each deploys independently. API contract is the boundary. More DevOps overhead before you can run anything end-to-end.

✓ Services deploy and scale independently ✓ Strong boundary enforcement ⚠ Cross-repo changes require coordinated PRs ⚠ Nothing runs end-to-end until API is stable ⚠ Slower iteration at this stage
C

Skills-Only First — Web App Never

Commit fully to the terminal + visual companion model. No web app — everything lives in Claude Code. Cloud sync is background artifact backup only. Rust services added when TypeScript skills hit perf limits.

✓ Maximum iteration speed ✓ Zero infra until needed ⚠ No team collaboration surface ⚠ Approval pipelines need a web UI ⚠ Blocks the collaboration vision entirely
Why A: you already have the monorepo and the proof-of-loop is one skill invocation away

The existing SDLC - Visual - Workflow - SoftwareEngineering-NewAge workspace is already Nx. The skills are already there. The diagram-driven pipeline is staged. Phase 1 means writing one new skill set and proving the hello-world loop fires end to end — today. The web app, Rust services, and AWS infra get added in the same workspace as capabilities, not as separate projects to coordinate. Nx affected builds mean the CI bill stays near zero while you're iterating.
