# Knowledge Base Blueprint

A diagram-driven migration platform is only reliable if its knowledge is partitioned cleanly and updated intentionally.

## Knowledge base set

| Knowledge base | Contents | Source of truth | Update rule |
|---|---|---|---|
| KB-01 Modeling Standards | UML/C4/ERD/BPMN/SysML/ArchiMate conventions, glossary | versioned reference docs | update when notation rules change |
| KB-02 Source Facts | extracted symbols, imports, dependencies, routes, schemas, configs | repo parsers + extraction jobs | regenerate on code change |
| KB-03 Behavior Evidence | traces, tests, runtime logs, recorded flows | verification and observability jobs | append-only evidence model |
| KB-04 Contracts | API schemas, message schemas, DB schemas, file contracts | extracted and human-approved schemas | update on contract change |
| KB-05 Target Platform Profiles | Rust framework patterns, memory/async constraints, TS framework patterns, infra profiles | curated profile docs | version per target |
| KB-06 Migration Patterns | keep/adapt/rewrite/defer examples, dependency substitutions, common gap resolutions | curated internal playbooks | grow per completed migration |
| KB-07 Agent Doctrine | personas, guardrails, skills, prompts, model routing | versioned agent/skill docs | update under approval |
| KB-08 Project Evidence & Decisions | ADRs, work orders, verifier reports, approvals, handoffs | project artifacts | append and supersede via approval |

## Retrieval priority order

1. project-local truth (current repo, current task, current evidence)
2. approved project ADRs and contracts
3. target platform profiles
4. migration patterns and prior examples
5. general modeling standards

## Storage shape

### Structured stores

- JSON ledgers for symbols, contracts, gaps, work orders
- relational tables for projects, runs, approvals, artifact manifests
- object storage for larger evidence bundles and exports

### Human-readable stores

- markdown ADRs
- markdown handoffs
- markdown diagram descriptions
- glossary and conventions docs

## Minimum structured schemas

### Symbol record

- id
- file path
- kind
- exported?
- inputs
- outputs
- side effects
- dependencies
- runtime surfaces
- source subsystem
- target subsystem

### Work order record

- id
- initiative
- phase
- role
- scope
- objective
- acceptance criteria
- dependencies
- risk
- approval required
- verifier

### Evidence record

- id
- artifact path
- generated by
- timestamp
- claim supported
- verification method
- verdict

## Governance rules

- extracted facts and generated interpretations must remain distinguishable
- every generated artifact should declare its inputs and generator
- high-risk migration rules should reference concrete evidence or prior examples
- knowledge bases should be packageable for handoff and offline review
