# Documentation Tools

This folder contains tools for managing third-party documentation.

## Generate Master Documentation Script

The `generate-master-documentation.cjs` script combines all `.md` files from a specified folder and its subfolders into a single master documentation file.

### Usage

```bash
node generate-master-documentation.cjs <folder-path>
```

### Features

- **Recursive Search**: Finds all `.md` files in the specified folder and subfolders
- **Duplicate Prevention**: Automatically deletes existing master files to prevent duplication
- **Organized Output**: Creates `master-{folder-name}-documentation.md` in the target folder
- **Structured Content**: Each file becomes a numbered section with file path reference
- **Error Handling**: Continues processing even if individual files have errors

### Example

```bash
# Generate master documentation for Chrome Extension API docs
node generate-master-documentation.cjs chrome-ext-api

# This creates: chrome-ext-api/master-chrome-ext-api-documentation.md
```

### Output Structure

The generated master file includes:
- Header with generation timestamp and file count
- Numbered sections for each `.md` file
- File path references for each section
- Original content from each file
- Section separators between files

### Testing

The script has been tested on the `chrome-ext-api` folder containing 70 `.md` files (1 root + 69 in subfolder), successfully generating a 30,000+ line master documentation file.

# DOCX Generation Modules

Standalone extraction of the DOCX generation modules and supporting components from the patient-record-generation app. Generates Microsoft Word (.docx) documents from encounter JSON records with configurable styles, headers, and page layout.

## Contents

- **src/docx/** – Core DOCX generation
  - `docx-generator.ts` – Main generator (Document, sections, numbering, header)
  - `docx-styles.ts` – Style config (title, headings, body, field label/value, header table, page margins)
  - `docx-header.ts` – Header table (patient info, DOB, MRN, column widths, borders)
  - `index.ts` – Public API
- **src/types/encounter-types.ts** – TypeScript types (EncounterRecord, Block, DocxStyleConfig, EncounterHeader, etc.)
- **src/cli/generate-docx.ts** – CLI for single file, patient folder, or batch

## Install

```bash
cd docx-generation-export
npm install
# or: pnpm install
```

## Usage

### Programmatic

```ts
import { generateDocx, createDocxGenerator, DEFAULT_DOCX_STYLE_CONFIG } from './src/docx/index.js';
import type { EncounterRecord } from './src/types/encounter-types.js';

const encounter: EncounterRecord = JSON.parse(fs.readFileSync('encounter.json', 'utf-8'));
const buffer = await generateDocx(encounter, { includeHeader: true });
fs.writeFileSync('output.docx', buffer);
```

### CLI

```bash
# Single file
npx tsx src/cli/generate-docx.ts --input=path/to/encounter.json

# Custom output
npx tsx src/cli/generate-docx.ts --input=encounter.json --output=out.docx

# All JSONs in a patient folder (expects patient folder to have encounters/ subdir)
npx tsx src/cli/generate-docx.ts --patient=patient-12345

# All patient folders (default base: output/Bravado-Unified-Patient-Folders)
npx tsx src/cli/generate-docx.ts --all

# Help
npx tsx src/cli/generate-docx.ts --help
```

## Encounter JSON shape

Input JSON must be an `IDEEncounterRecord` or `MMEEncounterRecord`: `schemaVersion`, `encounter`, `patient`, `provider`, `clinical`, `header` (with `table.rows`), and `blocks` (title, heading, paragraph, bullets). See `src/types/encounter-types.ts` for full definitions.

## Dependencies

- **docx** (^8.6.0) – Word document generation
- **tsx** (dev) – Run TypeScript CLI
- **typescript** (dev) – Build

## Usage

### CLI Usage

```bash
# Basic usage
pnpm nx run web-documentation:scrape -- https://docs.example.com/api

# Multiple URLs with custom output directory
pnpm nx run web-documentation:scrape -- \
  https://docs.example.com/api \
  https://docs.example.com/guide \
  --output-dir ./documentation

# With numbered filenames
pnpm nx run web-documentation:scrape -- \
  https://docs.example.com/api \
  --output-dir ./docs \
  --numbered

pnpm nx run web-documentation:scrape -- \
  https://api.example.com/docs \
  --browser \
  --headed \
  --output-dir ./api-docs
```

### Programmatic Usage

```typescript
import { DocumentationScraper, MarkdownConverter, FileWriter } from '@mm/web-documentation';

// Initialize components
const scraper = new DocumentationScraper({
  userAgent: 'My-Scraper/1.0.0',
  timeout: 30000,
});

const converter = new MarkdownConverter({
  includeCodeExamples: true,
  includeApiReference: true,
  includeToc: true,
});

const writer = new FileWriter();

// Scrape, convert, and save
const urls = [
  'https://docs.zoominfo.com/reference/overview',
  'https://docs.zoominfo.com/reference/searchinterface_searchcontact',
];

const pages = await scraper.scrapePages(urls);
const docs = pages.map(page => converter.convert(page));
await writer.writeFiles(docs, './documentation-3rd-party/Zoom-Info-API');
```

# Google Apps Script: IDE JSON to Google Docs Converter

This Google Apps Script converts AI-generated EncounterNoteDraft JSON files into formatted Google Docs and organizes them in Google Drive by patient status and name.

## Setup Instructions

### Step 1: Create a New Google Apps Script Project

1. Go to [https://script.google.com/](https://script.google.com/)
2. Click **"New Project"**
3. Name your project (e.g., "IDE JSON to Docs Converter")

### Step 2: Copy the Script

1. Open `ide-json-to-docs.gs` from this repository
2. Copy the entire contents
3. Paste into the Google Apps Script editor (replacing any default code)

### Step 3: Configure the Script

Update the `CONFIG` object at the top of the script:

```javascript
const CONFIG = {
  // Root folder ID where ACTIVE/INACTIVE folders live
  rootFolderId: '1Tb5v39DqRwk2341iYwOKqMXxA3e1Iu-8',
  
  // Leave empty for auto-detection (recommended)
  statusFolder: '',
  patientName: '',
  
  // Paste your JSON here, or use jsonFileId
  jsonInput: '',
  jsonFileId: '',
  
  // Options
  createJsonCopy: true,
  includeMissingData: false,
  includeClinicalInferences: false,
  autoDetect: true, // Recommended: automatically detect patient name and status
};
```

### Step 4: Grant Permissions

1. Click **"Run"** → **"generateRecordFromJson"**
2. When prompted, click **"Review Permissions"**
3. Select your Google account
4. Click **"Advanced"** → **"Go to [Project Name] (unsafe)"**
5. Click **"Allow"** to grant permissions:
   - Access to Google Drive (to create folders and files)
   - Access to Google Docs (to create documents)

## Usage

### Method 1: Paste JSON Directly (Recommended)

1. Copy the AI-generated JSON from your AI tool
2. In the script editor, paste it into `CONFIG.jsonInput`:
   ```javascript
   jsonInput: `{
     "schemaVersion": "1.0",
     "encounterId": "ide-1766464684536-2022-09-01",
     ...
   }`,
   ```
3. Ensure `autoDetect: true` in CONFIG
4. Click **"Run"** → **"generateRecordFromJson"**
5. The script will:
   - Automatically detect patient name from JSON header
   - Detect status (ACTIVE/INACTIVE) 
   - Create/use the appropriate folder structure
   - Generate the Google Doc
   - Save a JSON copy in the patient folder

### Method 2: Use Drive File ID

1. Upload the JSON file to Google Drive
2. Get the file ID from the file URL: `https://drive.google.com/file/d/{FILE_ID}/view`
3. Set `CONFIG.jsonFileId` to the file ID:
   ```javascript
   jsonFileId: '1a2b3c4d5e6f7g8h9i0j',
   ```
4. Click **"Run"** → **"generateRecordFromJson"**

## Folder Structure

The script creates the following structure in Google Drive:

```
Root Folder (1Tb5v39DqRwk2341iYwOKqMXxA3e1Iu-8)
├── ACTIVE/
│   └── {Patient Name} - {patientId}/
│       ├── IDE - {date} - {Patient Name}.doc
│       └── EncounterNoteDraft-IDE-{date}.json
└── INACTIVE/
    └── {Patient Name} - {patientId}/
        └── ...
```

## Auto-Detection Features

When `autoDetect: true`:

- **Patient Name**: Extracted from `draft.header.patientLegalName`, or searched for in existing folders by patient ID
- **Status**: Detected from `draft.status` field, or defaults to "ACTIVE" for IDE notes
- **Folder Matching**: If patient ID is found in encounterId (pattern: `ide-{patientId}-{date}`), searches existing folders to find the correct patient name

## Error Handling

The script validates:
- JSON syntax
- Required fields: `schemaVersion`, `encounterId`, `noteType`, `dateOfService`, `sections`, `missingData`, `clinicalInferences`
- Folder access permissions

Common errors:
- **"Invalid JSON"**: Check JSON syntax
- **"Missing required field"**: Ensure all required fields are present
- **"Cannot find folder"**: Verify `rootFolderId` is correct and you have access
