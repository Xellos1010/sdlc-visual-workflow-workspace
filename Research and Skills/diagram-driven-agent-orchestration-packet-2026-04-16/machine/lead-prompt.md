# Team Lead Prompt — Diagram-Driven Agent Orchestration Dashboard

## Environment
Ensure your agent-team environment is enabled before launching. This initiative assumes a Foundry-style lifecycle and machine-readable continuity.

## Objective
Build a model-backed, diagram-driven agent orchestration platform that can reverse-engineer codebases, synthesize architecture and migration artifacts, plan bounded work orders, and guide multi-agent execution across workstation and web surfaces.

## SDLC Context
Cycle: `discover → define → visualize → architect → plan → implement → verify → release → operate → diagnose → improve`
Current phase: `discover`
Continuity state: `.foundry/projects/diagram-driven-agent-orchestration-dashboard/current-task.json`
Work orders: `11-work-orders.md`

## Team Structure
Spawn the following teammates:

1. **systems-architect** — define product thesis, object model, artifact doctrine
2. **repository-cartographer** — define ingestion and symbol/dependency extraction
3. **diagram-architect** — define diagram taxonomy, view-selection rules, notation guardrails
4. **pseudocode-extractor** — define pseudocode ledger format and traceability rules
5. **contract-analyst** — define contract inventory and schema governance
6. **migration-strategist** — define gap matrix, keep/adapt/rewrite/defer, target profiles
7. **ux-dashboard-architect** — define shell, modes, drill-down chain, inspector behavior
8. **skill-designer** — package the reusable skill and templates
9. **collaboration-server-architect** — define project registry, approvals, evidence model
10. **verifier** — define pilot acceptance gates and evidence bundle structure

## Coordination Rules

1. Systems architect runs first and broadcasts the initial object model and authority stack.
2. Repository cartographer and diagram architect can begin once the object model is stable.
3. Pseudocode extractor and contract analyst start only after the repo-ingestion model is defined.
4. Migration strategist starts after pseudocode and contract formats exist.
5. UX dashboard architect can proceed in parallel once object model and diagram catalog are stable.
6. Skill designer packages only after artifact contract, personas, and skill matrix exist.
7. Verifier does not bless any stage without explicit evidence references.
8. Update continuity after each accepted work order cluster.

## Acceptance Gate

Before marking the packet ready for implementation, verify:

- artifact contract approved
- pipeline manifest approved
- dashboard shell defined
- knowledge bases defined
- work orders bounded and launchable
- `skill.zip` produced
