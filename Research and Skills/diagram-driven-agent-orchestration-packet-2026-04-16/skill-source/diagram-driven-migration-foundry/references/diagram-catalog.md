# Diagram Catalog

## Use these diagrams by default

- **C4 context** — external people/systems and the boundary of the system in scope
- **C4 container** — deployable apps, services, data stores, and major technology choices
- **Component diagram** — internal building blocks within a container
- **Sequence diagram** — runtime message order between actors/components
- **State machine** — lifecycle/state transitions for stateful systems
- **ERD** — persistence and entity relationships
- **DFD** — how data moves between processes and stores
- **Wireframe / screen flow** — operator-facing surfaces

## Use code-level diagrams selectively

Use class/code diagrams only for critical or complex components. Prefer auto-generation where possible.

## Migration-specific artifacts

These are required for migrations even though they are not classical diagrams:

- pseudocode ledger
- IO contract inventory
- dependency gap matrix
- keep/adapt/rewrite/defer ledger
- target mapping ledger
- work-order graph
