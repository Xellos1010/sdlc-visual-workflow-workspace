# PR policy

Default doctrine: one active integration PR per repository + project/client + feature set.

Use the PR matching continuity `activeBranch`, current work order, and canonical integration branch. If multiple plausible PRs exist, block and report ambiguity instead of creating another sibling PR.

Do not mark merge-ready unless verification evidence, acceptance criteria, lock release, continuity patch, rollback/release notes when needed, and blocker disposition are current.
