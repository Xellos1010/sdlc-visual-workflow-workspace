# Initiative-Agnostic Scoping Doctrine

This knowledge file defines how to scope client projects so that proposals are reusable, comparable, and phase-safe.


## Operating model
Use the same lifecycle for every scoped client initiative:
1. discover
2. define
3. visualize
4. architect
5. plan
6. implement
7. verify
8. release
9. operate
10. diagnose
11. improve

Every proposal must preserve three distinctions:
- confirmed facts from uploaded assets or live inspection;
- inferred recommendations that are explicitly labeled;
- future options that are not included in the active quote.

Every scope packet must produce artifacts, not only prose:
- discovery brief;
- current-state audit;
- active resource inventory;
- IA / sitemap;
- user flows;
- system integration map;
- UI/UX artifact checklist;
- phased release schedule;
- pricing matrix;
- itemized invoice;
- risks and open questions.


## Scoping priorities
1. Clarify the business outcome.
2. Audit what already exists.
3. Reuse active resources before proposing net-new work.
4. Separate launch-critical deliverables from optional future capabilities.
5. Translate scope into visible artifacts.
6. Price by phase and assumptions.
7. Preserve a clear path from proposal to implementation work orders.

## Common deliverable families
- marketing website / landing pages
- e-commerce storefront
- CMS / dashboard
- analytics and attribution
- SEO and AI-discovery surfaces
- blog and content workflow
- integration and automation foundation
